# Product — DevLeap

## Vision

DevLeap makes software engineering mastery a daily habit. Developers build real knowledge — not just theory — through short, focused practice sessions that adapt to what they know and what they need to improve.

## Target audience

Software developers at all experience levels who want to continuously sharpen their engineering skills: from juniors reinforcing fundamentals to seniors expanding into new domains.

## Problem being solved

Most developers know they should be continuously learning, but:
- Learning resources are fragmented and passive (read-only books, lengthy videos).
- There is no structured daily feedback on whether skills are improving.
- Retention is low without spaced repetition and active recall.
- Gamification makes consistent learning feel rewarding rather than obligatory.

## Value proposition

DevLeap gives developers a daily, structured, and measurable practice session that:
- Takes 5–10 minutes per day.
- Uses active recall and spaced repetition.
- Provides immediate explanations after every answer.
- Tracks real skill progress over time.
- Rewards consistency with XP, streaks, and levels.

## North-star metric

> **Percentage of users who complete at least three learning sessions per week.**

## MVP scope

### In scope

1. Registration and login (Supabase Auth).
2. User profile with XP, level, and streak.
3. One learning path: **Java Backend Developer**.
4. Skills and levels associated with the learning path.
5. Daily sessions with questions generated by a configurable algorithm.
6. Question types: multiple-choice, code output prediction, bug identification.
7. Explanations for correct answers.
8. XP calculation and daily streaks.
9. Skill progress tracking.
10. Session history.
11. User dashboard.
12. Minimal administrative interface for creating and editing questions.
13. Automated tests (unit, integration, e2e).
14. API documentation (Springdoc OpenAPI / Swagger UI).
15. Development seed data.

### Out of scope (MVP)

- Remote code execution submitted by users.
- Microservices architecture.
- Kafka / real-time messaging.
- Kubernetes orchestration.
- Real-time chat.
- Payments or subscriptions.
- Complex competitive leagues or season mechanics.
- Native Android or iOS applications.

These capabilities must remain possible to add later without rewriting the application core.

## Product metrics

| Metric | Description |
|--------|-------------|
| DAU / WAU | Daily and weekly active users |
| Session completion rate | % of started sessions that are completed |
| ≥ 3 sessions/week | North-star metric |
| Streak length | Average and maximum streak per cohort |
| Skill progression rate | Average mastery score increase per week |
| Retention (D7, D30) | % of users returning after 7 and 30 days |

## Important product definitions

| Term | Definition |
|------|-----------|
| **Learning path** | A curated sequence of skills (e.g. Java Backend Developer) |
| **Skill** | A discrete topic within a learning path (e.g. Spring Boot) |
| **Level** | A user's current position within a skill (1–N) |
| **Daily session** | A set of questions assembled by the learning engine for a user on a given day |
| **XP** | Experience points earned by completing sessions and answering questions correctly |
| **Streak** | The number of consecutive days a user has completed at least one session |
| **Mastery** | A 0–100 score representing how well a user has learned a skill |
| **Placement test** | An initial assessment that sets the starting level for a new user |
| **Spaced repetition** | A review scheduling algorithm that shows content again just before it is forgotten |
